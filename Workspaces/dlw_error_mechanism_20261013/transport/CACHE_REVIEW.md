# C 源插值与物理坐标接口独立审阅

2026-10-13。审阅对象：`source_cache.py`、`run_transport.py`、`common.py`，并与 `sources/common_sources.py` 的源定义对照。未修改被审代码。

## 结论

当前 C 固定网格运行中，三源的坐标转换和强迫积分接口一致；未发现漏掉时变边界项或重复添加该项的问题。五节点插值只近似辅助三源分解；主一步缺陷 d、主 RK4 导数 B、实际非线性轨道和四格源/传播交换实验仍逐步直接计算。因此主机制检验不依赖此插值。

## 坐标与时变边界

共同物理态为 z=(p,v)，SD native 态为 η=(p,w)。在固定网格及给定线性 ghost 闭合下，二者关系是

    η=A z+b(t),

其中 A 与时间无关，b(t) 包含给定下边界和参考 ghost。`to_native` 在每个时刻通过原 `recover_u`、`ghost_u` 计算完整仿射映射；`tangent_to_native` 只计算其线性部分 A。

对同一时刻两条轨道的误差，δη=Aδz。对参考残差，则

    r_native=f_native(η*,t)−η̇*=A(F_physical(z*,t)−ż*)=A r_physical。

因此对三源逐项调用 `tangent_to_native` 是正确做法；不应再给各源单独加 ḃ(t)。源生成阶段已包含精确 u_t 下边界、ghost 时间导数，以及 v_t=w_t+δ₀u_t。`SourceCache.source_parts` 的 `native_ref` 在当前查询时刻重新用 `reference` 和 `to_native` 得到，没有对参考态作插值。

## 强迫传播

每步 `step_and_jvp` 给出实际 RK4 步映射的导数 B。预存三源响应用同一个 B 传播。新加入的三源响应在零初值上，用原 native RHS 的解析 JVP 沿独立参考轨道作非齐次 RK4 四级积分，随后用线性逆映射回共同物理坐标。阶段时间分别为 t、t+dt/2、t+dt/2、t+dt，与强迫评估时间一致，三个方向以 batch 独立传播。

需保留一个准确表述：三源的非齐次积分沿精确参考轨道计算，主 B 沿真实 RK4 阶段求导。这两者不是逐步代数相同的表达；它们的近似一致性要由 `sum_parts_vs_one_step`、`max_local_parts_relative_residual` 检验。现有代码正确地单独记录了这项闭合误差，而没有强行归一化三源去匹配主缺陷。

## 插值证据及精度解释

当前使用 t=0,.0025,.005,.0075,.01 五个精确源节点的四次 Lagrange 插值。在四个未参与插值的区间中点分别直接计算精确源验证。

- 主 y/x 源最大相对 L2 误差 7.71175×10⁻⁸；最大逐点绝对误差 4.24730×10⁻¹⁰。
- wrap 源最大相对 L2 误差 2.96965×10⁻⁴；最大逐点绝对误差 1.56884×10⁻¹⁰。

wrap 相对误差较大，不能与主源一起报告为统一 10⁻⁵ 精度。报告应分别给出这些数值，并结合传播后的 wrap 绝对贡献判断其影响。四个留出点是数值验证，不是所有时间的严格插值误差上界；当前最有力的综合复核仍是插值三源响应之和与逐步直接计算主缺陷响应的独立闭合。
